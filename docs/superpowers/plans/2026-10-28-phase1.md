# Windows gfx1151 Phase 1 Implementation Plan

> **For agentic workers:** Use executing-plans for inline implementation and a
> fresh whole-branch reviewer. The user authorized autonomous execution.

**Goal:** Prove native Unlimited OCR 2 on the exact Windows ROCm stack or
preserve a minimal, evidence-based platform blocker.

**Architecture:** A small package performs strict preflight, pinned loading,
native infer/infer_multi calls and raw output validation. PowerShell creates
isolated environments. JSON evidence records actual execution and failures.

**Tech Stack:** CPython 3.10, mandated ROCm 7.14.1 wheels, candidate
triton-windows 3.7.1.post27, native Transformers 4.52.1.

**Spec:** ../specs/2026-10-28-phase1-design.md (original user mission is binding).

## Global constraints

- Native Windows only; physical gfx1151; BF16; batch size 1.
- Exact torch/vision/audio versions; no CPU or alternate model fallback.
- GitHub source 4d0bebab8714e0f3b0c811cd44bf422ddb49daae.
- HF model/code 9cf077c4b206e0e2a31879df937b0b0bcba3661c.
- Model code reviewed before execution; weights unchanged.
- Mark every skipped gate NOT TESTED or BLOCKED.

## Review focus

- Refuse wrong package identity, platform, GPU or CPU model tensors.
- Reject mutable revisions and tampered pinned model code.
- Preserve literal raw output and distinguish missing/duplicate/reordered pages.
- Windows paths with spaces/Chinese, UTF-8 and error manifests.
- Clean reproduction must never write to global Python or silently replace torch.
